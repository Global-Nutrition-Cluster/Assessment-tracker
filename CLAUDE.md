# GNC Nutrition Assessment Tracker: Claude Code brief

This file tells Claude Code how to build and maintain this repository. Read it fully before any change.

## 1. What we are building

A public, static web dashboard for the Global Nutrition Cluster (GNC). It shows which nutrition assessments are **planned, ongoing or completed** in each country, and where data is missing or outdated.

- **Owner:** Amadou Ndong, Information Management Officer, GNC
- **Audiences:** public and partners, country cluster coordinators and IMOs, GNC global team
- **V1 scope:** the **Planning view** only, starting with SMART and Rapid SMART surveys. The code must also handle MICS, DHS and IPC AMN rows without redesign.
- **Later (not in V1):** indicator results (GAM, SAM, MAM, mortality, morbidity), automatic DHS/MICS imports, and extraction of results from SMART report PDFs.
- **Visual reference:** the validated mockup from Claude Design, stored in `design/`. Match its layout, spacing and components. Where this brief and the mockup disagree, this brief wins.

## 2. Hard constraints

- **Static site on GitHub Pages.** No server, no database, no build step required to run the page. Plain HTML, CSS and JavaScript (ES modules).
- **No secrets and no paid APIs.** No Anthropic API key, no Mapbox or Google Maps key. Everything must run free on GitHub.
- **Automation runs in the cloud** (GitHub Actions), never on the owner's computer.
- **Data source of truth = a Google Sheet** maintained by the GNC, published to the web as CSV.
- **UI language: English.**
- Third-party libraries are loaded from a CDN with an **exact pinned version** (for example `leaflet@1.9.4`), or vendored in `assets/vendor/`.

## 4. Data pipeline

### 4.1 Source

- The Google Sheet URL (published as CSV) is stored as the repository **variable** `SHEET_CSV_URL` (Settings → Secrets and variables → Actions → Variables). Never hard-code it.
- The sheet may have a title row and a blank row above the header. **Detect the header row** by finding the row whose first cell is `Assessment ID`.

### 4.3 Normalisation rules (`scripts/build_data.py`)

Write each rule as a small, tested function.

1. **Assessment type:** trim and keep the raw value. Map it to a `type_group`: `SMART`, `Rapid SMART`, `MICS`, `DHS`, `IPC AMN`, otherwise `Other` (MSNA, NVA, mass MUAC screening, IPC AFI…). `Other` rows are kept in the JSON but hidden by default in the UI.
2. **Status:** one of `Planned`, `Ongoing`, `Completed`, `Not planned`. An unknown value produces a warning in `meta.json` and the row is kept with `status = null`.
3. **Display status** (drives all colours):
   - `Planned` → `planned`
   - `Ongoing` → `ongoing`
   - `Completed` + Validation starts with `Results released` → `released`
   - `Completed` otherwise → `completed` (awaiting release)
   - `Not planned` → `not_planned` (kept for the list filter, never shown in the map or timeline legends)
4. **Sub-stage:** the Validation text without the date in brackets (for example `Results released`, `Awaiting government approval`, `Data collection ongoing`).
5. **Release date:** parse `YYYY-MM-DD` from `Results released (YYYY-MM-DD)`. Otherwise `null`.
6. **Survey year:** the year token in the Assessment ID. Fall back to the start date year, then `null`.
7. **Funding:** `funded`, `partial`, `unfunded` or `null`. `funding_gap = true` when `partial` or `unfunded`.
8. **Dates:** output ISO `YYYY-MM-DD` or `null`. Never invent an end date.
9. **No date-based flags. Ever.** Start and end dates are indicative and change often. Do not compute or display "overdue", "late", "delayed", "start date passed" or any similar flag, in the data or in the UI.
10. **Freshness** (per country, computed in the browser so it follows filters): age in years of the most recent **released** result, using `release_date`, else `survey_year`. Buckets: `< 1 year`, `1–2`, `2–3`, `> 3 years`, `never`. Never use start or end dates.

### 4.4 Output

`data/surveys.json`: an array of objects with snake_case keys (`id`, `region`, `country`, `iso3`, `admin1`, `admin1_pcode`, `type_raw`, `type_group`, `status`, `display_status`, `sub_stage`, `start_date`, `end_date`, `release_date`, `survey_year`, `lead_org`, `partners`, `report_url`, `funding`, `funding_gap`).

`data/meta.json`: `{ "updated_at", "row_count", "warnings": [...] }`. The page shows "Data updated <date>" in the footer.

### 4.5 Workflow `update-data.yml`

- Triggers: daily schedule (night UTC) + `workflow_dispatch`.
- Steps: check out, set up Python, run `scripts/build_data.py`, run the tests, commit `data/*.json` **only if they changed**, with the message `data: refresh from Google Sheet`.
- If the CSV cannot be fetched or fails validation, the workflow fails and **does not overwrite** the existing JSON.
- Python standard library preferred (`csv`, `json`, `urllib`). No pandas unless clearly needed.

## 5. Page specification: Planning view

Top to bottom. Every block reads the same filtered dataset. The mockup in `design/` gives the exact look (colours, sizes, spacing); the decisions below were taken when comparing it with this brief (Oct 2026).

1. **Header:** GNC logo, divider, product name "Nutrition Assessment Tracker", and section tabs on the right. Only "Planning view" is shown until the Results, Methodology and Data & downloads pages exist (no dead links). Green 4 px bottom border.
2. **Page title:** "Planning view" + one-sentence description on the left; "Data as of <date from meta.json>" and "Source: country Nutrition Cluster submissions" on the right.
3. **Filter bar (sticky on desktop):** six single-choice dropdowns and a Reset button, no chips:
   - Period: "Calendar year YYYY" for each survey year (default current year) + "All years". Filters on `survey_year`, never on start/end dates.
   - Region, Country (the country list follows the region).
   - Assessment type: "SMART + Rapid SMART" (default), "All types", then each type group.
   - Status: All, Planned, Ongoing, Completed (= completed + released), Results released, Not planned.
   - Funding: All, Funded, Funding gap (partial + unfunded), Partially funded, Unfunded.
4. **KPI band:** four tiles with a status icon and a coloured top bar. Counts follow every filter except Status; clicking a tile sets the Status filter, clicking again clears it.
   - Planned: "X with funding gap"
   - Ongoing: "Data collection or analysis"
   - Completed: all completed surveys (released or not), sub-line "X awaiting release"
   - Results released: sub-line "In the selected period" (most SMART rows have no release date, so "last 12 months" cannot be computed reliably)
5. **Map** "Where assessments stand" (hero block). Leaflet (or MapLibre) with `geo/countries.geojson` (Natural Earth, fixed ISO3 codes) and **no paid tiles**. Segmented toggle "Status" / "Data freshness", a one-line caption, and the UN boundaries disclaimer under the map.
   - **Status mode:** a country takes the colour of its most advanced display status within the filtered set (`released` > `completed` > `ongoing` > `planned`). Legend: Planned, Ongoing, Completed (awaiting release), Results released, nothing else. Count markers per country: filled = funded, hollow = funding gap.
   - **Freshness mode:** countries coloured by the freshness bucket (rule 4.3.10) with the mockup scale (`--fresh-*` tokens, "Never" hatched); markers show the release year.
   - Hover shows a tooltip. Clicking a country filters the page to that country.
6. **Timeline (Gantt):** in plain SVG or HTML, no Gantt library. One row per survey, grouped by country, long groups collapsed with "Show N more surveys". 18 months on the x-axis (last 6 + next 12). Bars run from start to end date, coloured by display status, with the status icon in the row label. A survey without an end date is drawn as a one-month block; **no diamond and no "no end date" label** (the mockup shows one, the owner removed it). Dashed vertical "Today" line. Legend: status colours only. Note under the legend: number of surveys without a start date (listed only in the survey list) and "Dates are indicative."
7. **Coverage matrix:** countries as rows (with region), columns **SMART, Rapid SMART, MICS, DHS** (no IPC). A cell shows the status colour, icon and year of the latest survey of that type, plus "× N" when several surveys share that year; an empty cell means no survey on record. Cells that do not match the Status/Funding filters are faded. The country column stays frozen when scrolling horizontally.
8. **Survey list:** sortable table with Assessment ID, Country · Admin 1, Type, Status (icon + label), Start, End, Lead organization, Validation, Funding badge, Report link. Missing values read "Not reported" (grey italic). 12 rows per page with Previous/Next. "Export CSV" primary button (exports all filtered rows).
9. **Detail panel:** side panel (440 px) on desktop, bottom sheet on mobile (`design/Mobile – Survey detail sheet-html`). All fields, "Not reported" for gaps, a "Missing information: …" notice, and an "Open report" button (or "No report published yet").
10. **Footer:** "Global Nutrition Cluster · nutritioncluster.net" and "Assessment status is reported by country Nutrition Clusters. Start and end dates are indicative."

**URL state:** all filters and the map mode live in the query string (for example `?country=MLI&type=SMART&year=2026&map=freshness`), so a view can be shared by link.

## 6. Responsive behaviour and accessibility

- **Desktop ≥ 1200 px:** KPIs in one row, map and timeline side by side, matrix and list full width.
- **Tablet:** map and timeline stacked.
- **Mobile < 640 px:** KPI tiles in a 2 × 2 grid, map full width, timeline replaced by a list grouped by month, matrix scrolls horizontally with the country column frozen.
- Status is never conveyed by colour alone: always add a label or an icon.
- WCAG AA contrast, keyboard navigation for filters, tiles, list and panel, and `aria` labels on the map and SVG charts.

## 8. How to work in this repo

- **One feature per branch and pull request**, with a short description and a screenshot of the result. The owner reviews on the GitHub Pages preview.
- Suggested order: (1) data script + tests + workflow, (2) page skeleton + tokens + filter state, (3) KPI band, (4) survey list + detail panel, (5) map, (6) timeline, (7) coverage matrix, (8) responsive and accessibility pass.
- Keep functions small and readable: the owner is an IMO, not a full-time developer, and must be able to maintain the code. Comment the business rules (section 4.3) where they are applied.
- Never commit the source Excel file, personal data or secrets.
- Do not add a framework (React, Vue…) or a build tool without asking the owner first.
- When a rule here is unclear or a source value does not fit, ask, or log a warning in `meta.json`. Do not guess silently.

## 9. Acceptance checklist for V1

- [ ] The nightly workflow refreshes `data/surveys.json` from the Google Sheet, and a broken sheet does not break the site.
- [ ] No "overdue" or date-based flag appears anywhere.
- [ ] The KPI counts match the filtered list.
- [ ] The map toggles between Status and Freshness, and Freshness uses only release dates or survey years.
- [ ] The coverage matrix has exactly four columns: SMART, Rapid SMART, MICS, DHS.
- [ ] The page matches the mockup in `design/`, except where section 5 records a different decision.
